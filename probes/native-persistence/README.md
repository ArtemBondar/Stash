# Native persistence probe

This is a standalone Kotlin Toolchain experiment, not the Stash application or a production persistence implementation. It exercises Room 3.0.3 with bundled SQLite 2.7.1 on JVM and iOS simulator arm64. The checked-in launchers pin Kotlin Toolchain 0.14.0 and its distribution checksum; that toolchain uses Kotlin 2.4.20. The schema snapshots are generated by Room for each target.

From this directory, run:

```sh
./kotlin test -p jvm
./kotlin test -p iosSimulatorArm64
```

The iOS test requires macOS, Xcode, and an available iOS simulator. The first run may need network access to download the toolchain and dependencies. `kotlin.bat` provides the corresponding Windows launcher for JVM; the iOS target still requires a Mac.

Four tests per target cover reopening a saved item, committing an item and outbox row together and rolling both back on an injected failure, migrating and reopening version 1 data, and literal substring search before and after reopening. Search uses SQLite `instr`: `%` and `_` are literal, matching is case-sensitive, Unicode is not normalized, and an empty query matches all fixture rows.

The version 1 database is a **synthetic SQL fixture**, including the Room identity hash from the checked-in version 1 schema; it is not a database produced by a released Stash application. The migration adds a non-null note with an empty default. These tests do not establish production durability under crashes or power loss, concurrency behavior, synchronization, extension sharing, performance, or support for other targets.

## Android instrumentation

The separate `android-instrumentation` test-only harness builds the same Room source and shared search assertions with Android Gradle Plugin 9.0.1, KSP 2.3.7, and Gradle 9.1.0. It exists because Kotlin Toolchain 0.14.0's Android test task uses a mockable platform JAR on the host; its task graph does not offer an instrumentation task. This harness does not change the primary Toolchain build or production app. It needs Android SDK platform 36, an Android device or emulator, and a JDK compatible with Gradle 9.1.0. The checked-in Gradle wrapper downloads the checksum-pinned distribution on first use. From the probe directory:

```sh
android emulator start --headless Pixel_10 # or use an already connected device
cd android-instrumentation
./gradlew connectedDebugAndroidTest
```

On the local Pixel_10 emulator (API 37, arm64), the four instrumentation tests passed on 2026-11-28. They exercise the same four behaviors described above on a device, including the synthetic migration fixture. The Android test is regression verification; build and runner failures encountered during setup were not behavioral test failures. As with the other targets, this does not prove crash or power-loss durability.
